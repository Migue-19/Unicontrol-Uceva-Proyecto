# Sistema de Gestión de Solicitudes Académicas – UCEVA

## Descripción del Proyecto

Este repositorio contiene el desarrollo del proyecto académico orientado a la gestión de solicitudes académicas para estudiantes de la institución UCEVA.

El sistema busca facilitar el proceso mediante el cual los estudiantes pueden realizar solicitudes relacionadas con procesos académicos, permitiendo a los administradores gestionarlas y dar seguimiento de manera eficiente.

Este proyecto se desarrolla como parte de una actividad académica donde se aplican conceptos de **modelado UML, control de versiones y trabajo colaborativo utilizando GitHub**.

# Configuración del Repositorio

El repositorio fue configurado para garantizar buenas prácticas en el desarrollo colaborativo utilizando herramientas de control de versiones.

Se aplicaron reglas de protección en la rama principal para evitar cambios directos y asegurar que todas las modificaciones pasen por un proceso de revisión.

### Configuración aplicada

* Rama principal del proyecto: **main**
* Protección contra cambios directos en la rama principal
* Uso obligatorio de **Pull Requests**
* Revisión mínima de **1 aprobador** antes de fusionar cambios

# Flujo de Trabajo de Colaboración

Para el desarrollo del proyecto se implementa el modelo **GitHub Flow**, que permite mantener un desarrollo organizado y seguro.

## Estructura de ramas

La rama principal del repositorio es:

**main**

Todas las nuevas funcionalidades se desarrollan en ramas independientes creadas a partir de la rama principal.

Ejemplos de nombres de ramas:

feature/registro-solicitudes
feature/notificaciones
feature/historial-estudiante

---

# Proceso de Trabajo

El flujo de trabajo que debe seguir cada integrante del equipo es el siguiente:

1. Clonar el repositorio desde GitHub.
2. Crear una nueva rama a partir de **main**.
3. Desarrollar la funcionalidad correspondiente en esa rama.
4. Realizar commits con descripciones claras.
5. Subir los cambios al repositorio.
6. Crear un **Pull Request** hacia la rama **main**.
7. Esperar la revisión y aprobación del cambio.
8. Realizar el **Merge** una vez aprobado.

Este proceso permite mantener el control de cambios y evitar errores en la versión principal del proyecto.
